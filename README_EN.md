# TI-59 Zombie

**Texas Instruments TI-59 calculator emulator on ESP32-S3**

Faithful reproduction of the programmable TI-59 calculator (1977), based on emulation of the TMC0501 microprocessor, with an embedded web interface that also acts as an IDE. Arduino firmware for the ESP32-S3 (DevKitC-1 N16R8, 16 MB flash, 8 MB Octal PSRAM).

---

## Features

- **Full TMC0501 core emulation**: DSCOM, BROM, RAM, 8-level subroutine stack, BCD data registers, user flags, INV/2nd indicators.
- **Real-time pacing**: same speed as the original TI-59 (~7,100 instr/s) with a web-tunable "Old/New" mode.
- **14 "Solid State Software" library modules** with official numbering (see below).
- **Magnetic cards emulated** as JSON files in SPIFFS (480-step sides A/B, registers), with a card-sense microswitch.
- **Optional NFC reader** (MFRC522 + NTAG213 tags) reproducing the original reader's READ/WRITE flow, with motor ejection.
- **BLE thermal printer** (NimBLE backend) for the PC-100A printer emulation.
- **12-digit display** driven by an HT16K33 (16x8, I2C).
- **Embedded web IDE**: virtual calculator, program/card/module management, overlay editor with preview, SVG position panel.
- **Italian/English i18n** selectable from the web pages.

## Hardware

| Component | Notes |
|---|---|
| ESP32-S3-DevKitC-1 N16R8 | 16 MB flash, 8 MB Octal PSRAM |
| HT16K33 16x8 display | I2C, 12 digits, SDA=43 SCL=44, addr 0x70 |
| 9x5 keyboard | 14-pin matrix: rows GPIO1-9, cols GPIO10-14 |
| Magnetic cards | microswitch GPIO15 (card-sense), LED GPIO16 |
| RFID MFRC522 (optional) | shared SPI, CS=21, RST=45, power MOSFET GPIO41 |
| Eject motor (optional) | GPIO42 |
| BLE printer (optional) | Bluetooth LE (NimBLE) |
| microSD | CS=40, shared SPI bus SCK=18 / MOSI=17 / MISO=39 |
| Power | LiPo 3.7V + charging module + SPST switch |

**GPIO caution**: on the DevKitC-1 pins 22-34 are the internal flash/PSRAM bus (not exposed); writing to them blocks flash → WDT reset loop at boot. Use only the exposed pins (0-21, 35-48).

## Software architecture

- `ti59_zombie.ino` — firmware, FreeRTOS tasks and setup.
- `src/tms1500.cpp/h` — TMC0501 CPU emulator (program execution, decoding, registers).
- `src/library_module.cpp/h` — library module registry.
- `src/rom_XX.cpp/h` — module ROMs (generated by `rom_import_validator.py`).
- `src/keyboard.cpp/h` — keyboard matrix scan.
- `src/display.cpp/h` — HT16K33 driver.
- `src/cardemu.cpp/h` — magnetic card emulation on SPIFFS.
- `src/rfid_reader.cpp/h` — NFC reader (MFRC522 + NTAG213).
- `src/printer.cpp/h`, `src/ble_thermal_printer.cpp/h` — PC-100A printer and BLE backend.
- `src/wifilink*.cpp/h` — HTTP web server + embedded web IDE.
- `src/config.h` — pinout and constants.
- `data/` — SPIFFS contents: overlay SVG templates, `overlays.txt`, `overlay_pos.json`.

The CPU runs in a dedicated-priority task with a mutex (`g_cpuMutex`) protecting concurrent access from keyboard, WiFi and periodic saves.

## Building & flashing

1. Open `ti59_zombie.ino` in Arduino IDE (1.8.x or 2.x).
2. Install the Espressif **esp32** core (Boards Manager) and select **ESP32S3 Dev Module** (16 MB flash / 8 MB OPI PSRAM, USB-Serial-JTAG).
3. Required libraries: **MFRC522** (RFID only) and **NimBLE-Arduino** (BLE printer only). The others (WiFi, WebServer, SPIFFS, DNSServer, Preferences, Wire, SHA1Builder) ship with the core.
4. Flash the firmware.
5. Upload the `data/` folder to the SPIFFS filesystem ("ESP32 Sketch Data Upload" tool or `esptool` on the SPIFFS partition).

See `SETUP_ARDUINO_IDE_EN.md` for the complete board settings (Flash Size 16M, Partition Scheme Custom, etc.).

On first boot the board opens a **WiFi captive portal** (page `/setup`) to enter network credentials, stored in the `/wifi.json` file on SPIFFS (flashable with the `data/` folder).

## Security

- WiFi credentials live in the **`/wifi.json`** file on SPIFFS (no hardcoding, no NVS), downloadable/editable/reloadable from the `/setup` portal (`GET`/`POST /api/wifi/file`). Note: the file contains plaintext passwords — it belongs to the device owner.
- The `/wolf` (god mode) panel only activates if `/god_mode.txt` exists on SPIFFS.
